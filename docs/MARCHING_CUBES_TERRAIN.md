# Marching Cubes 地形

Minecraftの自然地形の階段状の見た目を、Marching Cubesで作った滑らかな3D地形として描画する。
ブロックデータ（BlockState）は削除も変更もせず、Voxelデータとして読むだけ。当たり判定はまだブロックのまま。

```
Minecraft Blocks → Density Field → Marching Cubes → Triangle Mesh → 独自描画
```

| 段階 | 実装（`src/client/java/chihalu/horror/client/terrain/`） | 内容 |
| --- | --- | --- |
| Minecraft Blocks | `SectionTerrainMesher`, `TerrainBlocks`, `VoxelGrid` | バニラのセクション構築用スナップショットから、セクションと周囲のブロックを地形種別に変換 |
| Density Field | `DensityField` | ブロック中心ごとの密度。固体は正、空気は負、isoLevel = 0 |
| Marching Cubes | `MarchingCubes`, `MarchingCubesTables` | 8頂点の密度 → Cube Index → Edge Table / Triangle Table → 交点の線形補間 |
| Triangle Mesh | `TerrainMesh` | 位置・法線・Terrain Type・光・インデックス。Minecraftに依存しない配列 |
| 独自描画 | `GpuTerrainMesh`, `TerrainRenderer`, `assets/horror/shaders/core/marching_terrain.*` | 独自パイプラインで不透明地形パスに描く |

`TerrainType` / `VoxelGrid` / `DensityField` / `MarchingCubesTables` / `MarchingCubes` / `TerrainMesh` は
Minecraftのクラスを使わない純Javaで、`terrainTest` でクライアントなしに検証できる。

## 対象ブロック

草ブロック、土、石、砂、砂利の5種類だけ（`TerrainBlocks`）。
木、葉、建築ブロック、鉱石、安山岩などの他の石、水、植物などはMarching Cubes化せず、通常の立方体のまま描く。
対象を増やすときは `TerrainBlocks` と `TerrainType` に追加する。

## Density Field

- 格子点はブロックの中心。固体（対象ブロック）= 正、それ以外 = 負、isoLevel = 0。
- solid = 1 / air = -1 だけだと、交点が常にブロック中心の中間（=ブロック面）に来るため、
  段差は45°の面取りにしかならない。2:1の階段では最大0.25ブロックの段差が残る。
- そこで各格子点の周囲7×7×7ブロックに二項分布のぼかし（1, 6, 15, 20, 15, 6, 1 を3軸）をかけ、
  「地形の量」を求める。平らな地面の最上段が +1、その上の空気が -1 になるよう正規化する。
  ぼかしは整数演算で、入力は周囲のブロックだけ。同じ座標は、どのセクションから計算しても完全に同じ値になる。
- 符号はそのブロック自身の固体/空気のまま（ぼかしで決めない）。ブロックが消えたり、隙間が埋まったりしない。
- 密度の絶対値を 1/3〜1 に制限する。交点はブロック中心間の 0.25〜0.75 に収まり、面はブロック面から最大0.25ブロックしか動かない。
- 周囲を地形に囲まれた空気（1×2のトンネル、2×2の通路、1段の隙間、1ブロックの穴）は、
  ぼかしが「固体」と判断しても密度を -1 に保つ。面が空間側へ膨らまないので、プレイヤーやカメラが面にめり込まない。

階段を理想的な坂（各段の上面の中心を結ぶ直線）と比べた最大のずれ（`terrainTest` の計算。ブロック単位）:

| 階段 | 1:1 | 2:1 | 3:1 | 4:1 | 6:1 |
| --- | --- | --- | --- | --- | --- |
| solid = 1 / air = -1 | 0.000 | 0.250 | 0.333 | 0.375 | 0.417 |
| この実装 | 0.000 | 0.062 | 0.085 | 0.125 | 0.189 |

## Marching Cubes

- 標準の手順どおり、セルごとに8頂点の密度を読み、Cube Index（isoLevelより下の頂点にビット）を作り、
  Edge Table で交差する辺を、Triangle Table で三角形を引き、辺上の交点を密度から線形補間する。
- 表は Paul Bourke の頂点・辺番号付け。Edge Table は定番の表と同一（テストで確認）。
- Triangle Table はクラス初期化時に生成する。曖昧な面（対角に固体が2つある面）の解き方を、その面の4頂点だけで決める
  （固体どうしをつなぐ）。元祖の表は同じ面を他の4頂点次第で別々に解くことがあり、隣り合うセルで輪郭が食い違って穴が開く。
  ここでは隣のセル（別のチャンクでも）が必ず同じ輪郭になる。
- 4辺より多い輪郭（鞍型）は平面でないため、単純な扇形分割だと面に張り付いた三角形や内向きの三角形ができる。
  全ての分割のうち、最も外を向かない三角形が一番外を向く分割を選ぶ。
- 頂点は格子の辺ごとに1つで、セクション内のセル間で共有する。三角形は地形の外から見て反時計回り。

## 法線

- Smooth Normal。三角形ごとのFlat Normalは使わない。
- ぼかした地形の量の勾配（中心差分）を、位置と同じ補間率で辺に沿って補間する。
  階段の段ごとの凹凸ではなく平均の坂の向きになるので、2:1の階段でも法線は理想の坂の法線から15°以内に収まる（テストで確認）。
- 囲まれた空気（トンネル・空洞）に接する頂点は、密度そのものの勾配へ寄せる（ぼかしは小さな空間をほとんど捉えないため）。
- 頂点が乗る辺の「固体→空気」の向きを、少なくとも cos 0.2 は向くよう補正する。
- どれも辺の両端の値だけから計算するので、チャンク境界の頂点は両側で同じ法線になる。

## チャンクと境界

- 16×16×16 のセクション単位で生成する。セクションは「最も小さい角が自分のブロック中心であるセル」を所有する。
  境界のセルは隣のセクションのブロック中心も読むため、メッシュは隣のメッシュがちょうど始まる所まで続く。
- 生成はバニラのセクション構築（ワーカースレッド）の中で行う。バニラのスナップショットは周囲26セクション分を含むので、
  必要な余白（下4・上5ブロック）はすべて同じ一貫したコピーから読める。
- 共有頂点は、辺の下端から上端へ向けて同じ式で計算するので、位置も法線もビット単位で一致する。
  描画時の座標はバニラ地形と同じ分け方（セクション原点 − カメラのブロック座標は整数、端数はGlobalsの `CameraOffset`）で、
  隣り合うセクションの頂点が画面上でもずれない。
- バニラはブロック変更時に周囲1ブロックのセクションだけ作り直す。地形面は下4・上5ブロック先まで読むので、その範囲のセクションも作り直す（`LevelExtractorMixin`）。
  隣のチャンクの読み込み・光の更新ではバニラが周囲のセクションを作り直す。
- 地形面は、バニラがそのセクションの新しいメッシュに切り替えるのと同じフレームで切り替わり、古いメッシュと一緒に解放される
  （`CompiledSectionMeshMixin`）。ブロックが全て隠れて何も描かないセクションも、地形面があれば空の共有メッシュにせず保持する。

## Mesh

`TerrainMesh` はセクションごとの三角形メッシュ（record）:

- `positions`: 頂点の位置（セクション原点からのブロック単位、float×3）
- `normals`: Smooth Normal（単位ベクトル、float×3、地形の外向き）
- `types`: Terrain Type（その頂点が属する地形ブロックの種別）
- `light`: 頂点の空気側のブロック光・空の光
- `indices`: 三角形のインデックス（3つで1三角形）

描画にもCollisionにも使えるよう、描画APIには依存しない。GPUへアップロードした後はCPU側の配列を捨てる（メモリ節約）。
Collisionで使うときは、同じ `MarchingCubes.mesh(...)` を必要な範囲だけ呼んで生成する想定。

## 描画

- 不透明地形パスの中、バニラ地形の直後・エンティティの前に独自パイプライン `horror:pipeline/marching_terrain` で描く（`LevelRendererMixin`）。深度はバニラと共通。
- 頂点（24バイト）: 位置、Terrain Typeの単色、バニラのライトマップ座標（ブロック光・空の光）、法線。インデックスは16ビット。
- 陰影: バニラのブロック面の明るさ（上1.0・下0.5・南北0.8・東西0.6）を、Smooth Normalでピクセルごとに連続的に混ぜる。
  昼夜・洞窟の明るさはバニラのライトマップ、霧・チャンクのフェードインもバニラと同じ（ホラー描画パックの霞もかかる）。
- カリングはバニラの可視セクション一覧（視錐台＋遮蔽）をそのまま使う。
- テクスチャ、PBR、Triplanar Mapping、AOはまだない。

## Vanilla地形との関係

- 対象ブロックのモデルをラップし（`HiddenTerrainModel`）、チャンクメッシュ生成時だけ何も出力しない。
  BlockStateはそのままなので、採掘・当たり判定・保存・サーバーは通常どおり。
- アイテム、落下中の砂・砂利、採掘のひび、設置直後の一時表示などは通常の立方体で描かれる。
- 対象ブロックに接する他のブロックの面は、隠れる前提で省略せずに描く（`BlockMixin`）。
  滑らかな面はブロックの内側へ最大0.25ブロック入るため、省略すると隙間から向こう側が透ける。
- Marching Cubes表示中は、既存の角丸め（`ContinuousSurfaceModel`、F8のホラー描画）を止める。
  他のブロックの面を正確な立方体に保ち、滑らかな面との継ぎ目がずれないようにするため。標準表示では従来どおり。

## デバッグ表示

- **F9**（キー設定「Horror：地形」で変更可）で切り替える: 標準のブロック → Marching Cubes → ワイヤーフレーム → …
- 起動時は Marching Cubes。
- 標準 ⇔ Marching Cubes の切り替えは全チャンクのメッシュを作り直す（ブロックを出す／隠す）。
  Marching Cubes ⇔ ワイヤーフレームは描き方だけが変わるので即時。
- ワイヤーフレームは、陰影付きの面の上に三角形の辺を暗い線で描く。GPUがワイヤーフレーム描画に対応しない場合は飛ばしてメッセージを出す。
- テストや調査用に `TerrainRenderer.drawnSections()` / `drawnTriangles()`（直前のフレームで描いた数）を読める。

## 負荷

- 生成は1セクションあたり約0.3ms（開発機での純Java計測、ブロック読み取りを除く）。バニラのセクション構築と同じワーカースレッドで行い、描画スレッドでは行わない。
- 描画は地形面のあるセクションごとに1回の描画呼び出し。GPUバッファは初回描画時にアップロードする。
- 地下では、対象ブロックと対象外の不透明ブロック（安山岩、鉱石、深層岩など）の境界にも面ができ、
  対象外ブロックの面も省略されなくなるため、見えない面が増える。対象ブロックを増やすほど減る。

## 既知の制限

- 当たり判定・選択枠はブロックのまま。坂では足元が最大0.25ブロック浮く／沈む。
- 草花・雪の層などの植物や薄いブロックは元の位置のまま描かれ、面が動く所では浮き・埋まりが出る。
- 単色なので、草ブロックの側面（土の部分）も草の色になる。Terrain Typeごとの色が頂点間で混ざる。
- 4:1より緩い階段は、わずかな段差（最大0.13〜0.19ブロック）が残る（陰影は滑らか）。
- 1ブロックの穴・出っ張り・トンネルは形を保つため、45°の面取りに近い形になる。
- ネザーでもオーバーワールドの陰影値を使う。
- 他の描画Mod（Sodium・シェーダーMod等）との組み合わせは未検証。

## 検証

- `bash gradlew build` で `terrainTest`（純Java、約13万件の検査）を実行する:
  - 表: Edge Table が定番の表と一致、全256ケースで三角形が外（空気側）を向き、交差する辺をちょうど使う。
  - 平らな地面はブロック上面に一致し、法線は真上。
  - 階段 1:1〜4:1 が上の表のずれ以内（比較用の solid = 1 / air = -1 では2:1で0.24以上ずれることも確認）。
    2:1の階段の法線が平均の坂から15°以内。滑らかな丘で法線が三角形と逆を向かない。
  - 固体のブロック中心は内側、空気は外側（密度の符号）。頂点はブロック面から0.25以内。
  - 1×2トンネルの内側に頂点が入らない。
  - 3×3×3セクションのランダム地形（洞窟・張り出し・穴あり）で、全ての辺がちょうど2枚の三角形に逆向きで共有される
    （穴・亀裂なし、向きが一貫）。境界の共有頂点は両セクションで位置・法線がビット単位で一致。
- `bash gradlew runClientGameTest`（ウィンドウが開く）の `MarchingTerrainClientTest`:
  チャンク境界をまたぐ丘（1:1の石の崖、2:1・3:1の草の階段、斜めの階段、砂浜、砂利、池、木、トンネル、崖の鉱石、坂の草花）を作り、
  標準・Marching Cubes・ワイヤーフレームの3表示で撮影する。一部はホラー描画パックを外した素の色でも撮る。
  Marching Cubes表示で地形面が描かれていない場合は失敗する。画像は `build/run/clientGameTest/screenshots/`。
- 画面なしの環境では、Xvfb と Mesa（llvmpipe）で実行できる。XvfbのGLXにはsRGB対応の設定がないため、SDLにEGLを使わせる:
  `SDL_VIDEO_FORCE_EGL=1 xvfb-run -a -s "-screen 0 1280x800x24" bash gradlew runClientGameTest`
